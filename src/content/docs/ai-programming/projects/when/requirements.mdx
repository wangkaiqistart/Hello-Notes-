## MVP 主流程

1. 通过 HTTP API 提交延时消息。
2. 持久化消息和投递状态。
3. 由单节点时间轮调度到期消息。
4. 通过 HTTP 或 Kafka Sink 投递到下游。
5. 记录结果并支持失败重试和基础观测。

## 训练营边界

三周版本优先保证核心链路、可部署性和清晰验收，不同时实现所有 Sink、管理台增强、复杂权限、死信队列和多语言 SDK。后续扩展必须作为独立需求进入队列。

## 关键非功能要求

生产可用至少要讨论消息不丢、重复投递、幂等、故障恢复、节点扩缩容和运行可观测，而不能只验证“接口返回成功”。
