## 需求共性

订单超时、定时通知、延迟重试、审批超时、风控触发和延时归档，本质都是在未来时间点触发一次动作。业务通常同时关心时间精度、消息可靠性、幂等和可追溯性。

## 方案边界

- 消息中间件的延时能力通常绑定具体中间件。
- SDK 方案容易受大 Key、业务 Redis 和客户端形态限制。
- 任务队列、任务调度平台和云服务解决的是相邻问题，不一定适合做通用延时基础设施。
- 多级时间轮是值得研究的调度实现，但仍需补充持久化、故障恢复和投递语义。

When 的差异化方向是做一个独立、可部署、面向多种下游的延时投递服务。
