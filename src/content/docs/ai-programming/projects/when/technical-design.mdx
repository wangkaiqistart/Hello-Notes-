## 组件关系

- HTTP 对外接收消息，内部模块负责校验和持久化。
- ETCD 负责节点注册、心跳和 Controller 协调。
- Redis 保存消息和投递状态。
- 多级时间轮负责从秒级到更长时间范围的调度。
- Master/Slave 负责副本同步和故障切换。
- Sink 负责把到期消息投递到下游。

## 关键语义

“至少一次”意味着故障恢复时可能重复投递，因此下游必须配合幂等设计。不能把内存时间轮本身当作可靠存储；调度、持久化、同步和重放边界需要分别验证。

## 实施顺序

先跑通单节点提交、持久化、调度和投递，再增加集群协调、副本同步和故障切换。每一步都应有可重复的测试和故障场景。
