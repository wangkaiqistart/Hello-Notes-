## 总体路线

核心阶段采用 JDK 21、Spring Boot 3.x、Spring AI Alibaba 和 SQLite，自己控制 ReAct Loop，把模型协议转换与 Agent 执行循环分开，避免框架自动执行 Tool 导致重复调用。

## 关键设计

- Provider 负责模型名称到 ChatModel 的显式映射。
- ReAct Loop 负责观察、决策、Tool 调用和退出条件。
- Memory 以文件和结构化状态承载，注入 system prompt 时区分来源和生命周期。
- Tool 统一注册，屏蔽内置工具、MCP 和 Java Bean 的来源差异。
- Web Service、CLI 和 Channel 复用同一运行时内核。

## 设计边界

先保证单体运行时的可理解性和可测试性，再为多实例、外部状态、权限和审计预留扩展点。不要在核心循环尚未稳定时过早引入分布式复杂度。
