## Skill 的工程含义

Skill 不是更长的 Prompt，而是一份带有触发条件、执行流程、边界和辅助资源的能力模块。好的 Skill 至少要回答：什么时候使用、需要什么输入、按什么步骤执行、如何验证结果。

## 两类价值

- **能力提升**：让 Agent 学会原本不会的工具或流程。
- **偏好编码**：把团队的工程判断、质量标准和禁止事项固定下来。

Skill 应采用渐进式加载：元数据用于发现，正文用于执行，参考资料和脚本只在需要时加载。

## Superpowers 的启发

Superpowers 的核心不是某一条命令，而是把“写规格、写计划、分派任务、实现、Review、测试、收尾”组织成连续工作流。它说明 Skill 可以承载过程纪律，而不只是增加工具数量。

## 沉淀准则

1. 先记录真实重复发生的任务，再抽象 Skill。
2. 把输入、输出、失败处理和验证命令写清楚。
3. 能由脚本验证的规则不要只写在自然语言里。
4. 定期删除过时、重复和无法验证的 Skill。
