## 两者分别解决什么

- **SDD（Spec-Driven Development）**解决“想清楚”：把目标、范围、用户故事、约束和验收标准写成可追踪的规格。
- **Harness Engineering**解决“做可靠”：把上下文、规则、权限、工具、流程和检查机制组织成可执行系统。

只做 SDD，可能得到一份清楚但无法稳定执行的计划；只做 Harness，可能让 AI 很守规矩地完成了错误目标。两者要形成闭环。

## 最小闭环

1. 写清目标、非目标和验收标准。
2. 准备项目说明、参考资料和运行环境。
3. 按可独立验收的任务执行。
4. 用测试、构建、Review 和运行证据检查结果。
5. 把重复出现的经验提炼成规则、模板或 Skill。

## 三种落地模式

| 模式                | 适合场景                 | 特点                       |
| ------------------- | ------------------------ | -------------------------- |
| 专业 SDD 工具       | 从零开发、需求复杂的项目 | 流程完整，中间产物多       |
| 手工规格 + 增量任务 | 已有系统和小步变更       | 控制灵活，维护成本低       |
| 轻量项目规则        | 小型任务或早期探索       | 启动快，但必须补充外部验证 |

选择模式时，重点看任务规模、变更风险和团队是否能维护中间产物。
