## 七层观察框架

看到新工具时，先判断它解决哪一层问题，而不是先比较宣传页上的功能数量。

| 层次         | 主要问题               | 典型内容                              |
| ------------ | ---------------------- | ------------------------------------- |
| 模型层       | 谁负责推理和生成       | 基础模型、推理模型、长上下文模型      |
| 工具层       | AI 能执行什么动作      | 编辑器、终端、文件、浏览器、数据库    |
| 配置与约束层 | AI 应该遵守什么规则    | `AGENTS.md`、`CLAUDE.md`、权限、Hooks |
| 协作机制层   | 复杂任务如何分工       | Plan、Subagent、Review、任务隔离      |
| 协议与生态层 | 如何连接外部能力       | MCP、A2A、插件和共享 Skill            |
| 工作流层     | 什么时候运行、怎样验收 | CI/CD、自动化、测试和发布流程         |
| 方法论层     | 如何稳定地产生结果     | SDD、Harness、Loop Engineering        |

## 三类典型场景

- **新模块开发**：需要模型、代码工具、项目上下文、任务约束和测试闭环。
- **陌生大型项目改造**：先建立代码地图、边界和参考实现，再让 AI 分批修改。
- **接入 CI/CD**：把触发、权限、检查、人工审批和失败回滚写成流程。

## 选型原则

1. 先找当前流程的瓶颈，再找对应层的工具。
2. 优先选择能留下中间产物和验证证据的工具。
3. 把权限、数据边界和退出条件作为选型条件，而不是上线后的补丁。
4. 工具可以替换，任务模型、验收标准和工程约束应保持稳定。
