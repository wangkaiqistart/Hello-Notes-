智能体开发范式，是指构建自主智能系统时采用的标准化开发路径。常见路线可以分成两类：**低代码开发**和**编码开发**。

低代码更偏向“可视化拖拽 + 配置设计”，适合快速验证和轻量落地；编码开发更偏向“手写代码 + 定制框架”，适合复杂业务、深度定制和生产级系统。

<Aside type="tip" title="核心结论" icon="rocket">
  低代码和编码开发不是互相替代的关系，而是互补关系。选型时要看需求复杂度、开发资源、时间成本、后续迭代和安全性能要求。
</Aside>

## 两种范式

<Tabs>
  <TabItem label="低代码开发" icon="puzzle">
    低代码开发的核心是把复杂开发动作封装成可配置组件，让开发者通过拖拽、参数配置、流程编排来快速搭建 Agent。

    它适合标准化程度较高、流程相对清晰、对性能和安全没有极端要求的场景。常见平台包括 Dify、Coze、Agentar 等。
  </TabItem>
  <TabItem label="编码开发" icon="terminal">
    编码开发的核心是用代码控制完整系统能力，包括模型调用、工具接入、状态管理、业务逻辑、多智能体协作和部署运行。

    它适合复杂业务逻辑、高性能要求、高安全要求、多系统集成和长期演进项目。常见工具链包括 LangChain、LangGraph、Docker 等。
  </TabItem>
  <TabItem label="混合开发" icon="random">
    实际项目里，两种方式经常会一起用：先用低代码快速验证原型，再把核心复杂功能用编码方式重构；或者核心系统用编码开发，后台配置、知识库流程、运营工具用低代码补齐。

    混合开发的价值是同时获得效率和能力，而不是在两者之间硬选一个。
  </TabItem>
</Tabs>

## 低代码开发范式

低代码开发强调轻量化、快速落地。它更像是把 Agent 开发所需的常见能力做成平台组件，开发者主要负责选择组件、配置参数和编排流程。

<CardGrid>
  <Card title="技术架构" icon="setting">
    常见结构是组件层、编排层、部署层。平台负责封装能力，用户负责组合能力。
  </Card>
  <Card title="核心特征" icon="rocket">
    低门槛、高效率、强标准化，适合让非专业开发者或初级开发者快速上手。
  </Card>
  <Card title="典型场景" icon="information">
    快速原型验证、业务人员自主开发、中小企业轻量化需求、内部效率工具。
  </Card>
  <Card title="代表平台" icon="star">
    Dify、Coze、Agentar 等，通常提供工作流编排、知识库、插件和发布能力。
  </Card>
</CardGrid>

### 优劣势

| 角度 | 说明 |
| --- | --- |
| 优势 | 周期短、成本低、上手快、标准功能维护简单 |
| 劣势 | 定制化弱、灵活性不足、平台依赖较强、迁移成本较高 |

## 编码开发范式

编码开发强调专业化、深度定制。它不是只写几个接口，而是围绕 Agent 的完整生命周期搭建工程体系。

<CardGrid>
  <Card title="技术架构" icon="setting">
    常见结构是基础层、能力层、业务层、部署层，系统边界和能力组合都由工程代码控制。
  </Card>
  <Card title="核心流程" icon="random">
    从需求分析、模型选型、系统设计、开发实现，到测试、部署和持续迭代。
  </Card>
  <Card title="典型场景" icon="warning">
    复杂业务逻辑、高实时性、高性能要求、高安全要求、多智能体协作和企业系统集成。
  </Card>
  <Card title="主流工具链" icon="terminal">
    LangChain、LangGraph、Docker 等，用来支撑编排、状态管理、工具接入和部署运行。
  </Card>
</CardGrid>

### 优劣势

| 角度 | 说明 |
| --- | --- |
| 优势 | 定制化强、能力上限高、性能可优化、自主可控 |
| 劣势 | 周期长、成本高、学习门槛高、后续维护要求高 |

## 核心差异

| 维度 | 低代码开发 | 编码开发 |
| --- | --- | --- |
| 核心逻辑 | 配置化、可视化 | 代码化、定制化 |
| 开发主体 | 业务人员、初级开发者 | 专业开发者、算法工程师 |
| 开发周期 | 1-7 天 | 1-3 个月以上 |
| 定制化程度 | 低到中 | 中到高 |
| 成本 | 低 | 高 |
| 自主可控性 | 低，依赖平台 | 高，自主掌控 |
| 适用规模 | 个人、小微企业、轻量场景 | 中大型企业、复杂项目 |

## 如何选择

<Steps>

1. **看需求复杂度**：标准化需求优先低代码，复杂定制需求优先编码开发。

2. **看开发资源**：没有技术团队时先用低代码，有工程团队时可以考虑编码开发。

3. **看时间成本**：快速落地优先低代码，长期投入和长期演进优先编码开发。

4. **看未来迭代**：需求稳定可以低代码，需求多变、规则复杂更适合编码开发。

5. **看性能和安全**：高并发、高安全、强合规、深度私有化场景优先编码开发。

</Steps>

<Aside type="note" title="混合使用思路">
  核心复杂功能用编码开发，辅助标准化功能用低代码配置；快速原型先低代码验证，验证成立后再用编码方式重构生产系统。
</Aside>

## 未来趋势

<CardGrid>
  <Card title="低代码更可定制" icon="puzzle">
    平台会增强插件、开源组件和扩展能力，减少“只能按平台规则来”的限制。
  </Card>
  <Card title="编码框架更轻量" icon="terminal">
    框架会继续降低学习成本，把复杂编排、状态管理和部署能力封装得更易用。
  </Card>
  <Card title="混合开发成主流" icon="random">
    项目会越来越倾向于用低代码拿效率，用编码开发拿能力上限。
  </Card>
</CardGrid>

## 总结

<Aside type="tip" title="速记" icon="star">
  低代码开发是**效率优先**，适合轻量、标准化、快速落地场景；编码开发是**能力优先**，适合复杂、定制化、长期演进场景。

  选型不是二选一，而是根据需求、资源和成本选择最合适的组合。
</Aside>
