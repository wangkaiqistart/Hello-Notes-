大模型可以先理解为一种通过海量数据训练出来的 AI 系统。它能阅读、理解、生成内容，也能在一定程度上完成翻译、总结、问答、代码编写、图像理解等任务。

<Aside type="tip" title="核心理解" icon="rocket">
  大模型不是数据库，也不是简单的规则程序。它的核心能力来自训练后的参数和预测机制：根据上下文，预测下一个最可能出现的内容。
</Aside>

## 什么是大语言模型

大语言模型通常指 LLM，也就是 Large Language Model。它主要处理文本，通过学习大量语料中的语言规律、知识关联和表达模式，形成理解与生成自然语言的能力。

<CardGrid>
  <Card title="参数规模大" icon="database">
    参数可以理解为模型内部保存知识和模式的“权重”。参数规模越大，模型容量通常越强，但训练和运行成本也更高。
  </Card>
  <Card title="核心机制是预测" icon="puzzle">
    模型会根据前文语境，计算下一个 Token 的概率分布，再选择更合适的内容继续生成。
  </Card>
  <Card title="具备通用能力" icon="star">
    同一个模型可以处理问答、写作、翻译、代码、信息抽取等多种任务。
  </Card>
</CardGrid>

一句话：大语言模型的本质，是一个通过大量文本训练出来的“语言预测系统”。

## 大模型开发四阶段

大模型从“会续写文本”到“能稳定回答问题”，通常会经历几个关键阶段。

<Steps>

1. **预训练 Pretraining**：让模型阅读海量文本，学习语言规律、常识知识和基础推理模式。这个阶段算力消耗最大，周期也最长。

2. **监督微调 SFT**：用高质量问答、指令和示例训练模型，让它更懂人类指令，知道用户问什么时应该怎么回答。

3. **奖励建模 Reward Modeling**：训练一个评价模型，用来判断不同回答的好坏，为后续优化提供“评分标准”。

4. **强化学习 RLHF**：基于奖励模型继续优化，让模型输出更符合人类偏好、更安全、更稳定的回答。

</Steps>

| 阶段 | 目标 | 重点 | 成本特点 |
| --- | --- | --- | --- |
| 预训练 | 学语言、学常识、打基础 | 海量数据与大规模算力 | 成本最高 |
| SFT 微调 | 学会听懂指令 | 高质量人工标注问答 | 成本相对较低 |
| 奖励建模 | 建立回答质量标准 | 对多个回答进行排序 | 数据质量很关键 |
| RLHF 强化学习 | 让回答更符合偏好 | 根据奖励信号持续优化 | 工程复杂度较高 |

## Transformer 架构

Transformer 是现代大模型的核心架构。它的重要价值，是让模型可以更高效地理解上下文关系，并支持大规模并行训练。

<CardGrid>
  <Card title="里程碑意义" icon="approve-check">
    Transformer 让大模型具备了更强的上下文建模能力，是 GPT、BERT 等模型的重要基础。
  </Card>
  <Card title="自注意力机制" icon="puzzle">
    模型在处理一句话时，会关注句子中不同词之间的关系，而不是只按顺序机械读取。
  </Card>
  <Card title="并行处理能力" icon="setting">
    相比传统序列模型，Transformer 更适合利用 GPU 并行训练，因此能支撑大规模模型训练。
  </Card>
</CardGrid>

<Aside type="note" title="理解方式">
  自注意力可以简单理解为：模型会判断当前词和上下文里哪些词关系更重要，再基于这些关系理解整句话。
</Aside>

## Token 是什么

Token 是大模型理解和处理文字的最小单位。它不一定等于一个汉字、一个单词或一个字符，而是模型分词器切出来的片段。

<CardGrid>
  <Card title="模型的原子单位" icon="information">
    模型不是直接理解整段文字，而是先把文本切成 Token，再对 Token 序列进行计算。
  </Card>
  <Card title="降低计算复杂度" icon="setting">
    模型只需要处理有限数量的 Token 组合，而不是直接处理无限复杂的自然语言。
  </Card>
  <Card title="影响上下文长度" icon="chart">
    上下文窗口通常按 Token 计算。输入越长，Token 越多，可用于推理和生成的空间就越紧张。
  </Card>
</CardGrid>

举个简单例子：`I love AI` 可能会被拆成 `I`、`love`、`AI` 这样的 Token；中文也会根据分词规则拆成不同片段。

## 大模型如何生成内容

大模型生成内容不是一次性写完整篇，而是一步一步预测下一个 Token。

<Steps>

1. **输入与拆分**：用户输入文本，Prompt 会被分词器拆成一串 Token。

2. **上下文编码**：Transformer 会理解这些 Token 之间的关系，形成上下文表示。

3. **概率计算**：模型根据当前上下文，计算下一个 Token 的候选概率。

4. **采样输出**：从候选结果中选出一个 Token，作为下一步输出。

5. **迭代生成**：把新生成的 Token 加回上下文，重复预测、采样、生成，直到满足停止条件。

</Steps>

<Aside type="tip" title="关键点">
  大模型的生成过程可以记成：拆 Token → 理解上下文 → 预测下一个 Token → 追加到上下文 → 继续预测。
</Aside>

## 大模型常见分类

大模型不只处理文字。按输入和输出能力，可以分成多种类型。

<Tabs>
  <TabItem label="文本大模型">
    主要处理自然语言和代码，擅长问答、总结、翻译、写作、信息抽取和代码生成。常见代表包括 ChatGPT、Claude、Gemini、豆包等。
  </TabItem>
  <TabItem label="多模态大模型">
    能同时处理文本、图片、音频、视频等多种信息，适合图文理解、视觉问答、语音交互和复杂场景分析。
  </TabItem>
  <TabItem label="生成类模型">
    根据文本或其他输入生成图片、语音、视频或 3D 内容，例如文生图、图生图、语音合成、视频生成等。
  </TabItem>
</Tabs>

| 类型 | 核心能力 | 常见场景 |
| --- | --- | --- |
| 文本大模型 | 文本理解、生成、推理、代码 | 问答、写作、翻译、编程 |
| 多模态大模型 | 处理文本、图像、音频、视频 | 图文理解、视觉问答、语音助手 |
| 图像生成模型 | 文生图、图生图、图像识别 | 设计草图、插画、素材生成 |
| 语音大模型 | 语音识别、语音合成、音乐生成 | TTS、ASR、语音交互 |
| 视频生成模型 | 文生视频、图生视频、视频编辑 | 短视频生成、分镜、广告创意 |
| 3D 生成模型 | 文本或图片生成 3D 模型 | 游戏资产、空间设计、原型建模 |

## 总结速记

<Aside type="tip" title="速记" icon="star">
  大模型 = 海量数据训练 + 大规模参数 + 基于上下文预测下一个 Token。

  开发流程可以记成：预训练打基础，SFT 学指令，奖励建模定标准，RLHF 对齐人类偏好。

  工作逻辑可以记成：文本先变 Token，Transformer 理解上下文，再一步步预测并生成结果。
</Aside>
