> **范围重点**：MVP 要形成从提交到投递的完整闭环，并把持久化、集群、观测和部署纳入可验收范围。

## 核心功能

1. 提交延时消息，指定投递时间和 Sink 配置。
2. 查询消息状态和投递结果。
3. 在到期时投递到 HTTP 或 Kafka。
4. 支持取消尚未投递的消息。
5. 消息持久化，节点重启后可恢复。
6. 多节点注册、组集群、选 Controller 和感知上下线。
7. 时间轮 Master/Slave 副本和故障接管。
8. 提供业务 API、管理 API 和基础管理台。
9. 提供指标、结构化日志和健康检查。

## 三周 MVP 的边界

- 先支持 HTTP、Kafka 两种 Sink；
- 先完成单机闭环，再扩展三节点集群；
- 先实现基础重试和状态机，不做复杂优先级、死信和跨地域；
- 支持 Docker Compose、单节点和 Kubernetes 基础部署。

## 不做什么

- 不把 When 做成完整消息队列；
- 不替代通用 Cron 调度平台；
- 不在第一阶段实现所有协议和所有云厂商适配；
- 不为了理论一致性引入 Raft/Paxos 级别的复杂度。

## 验收主链路

消息从提交走到持久化、等待调度和到期投递；投递结果分别进入成功、重试或失败状态。取消必须检查当前状态，避免与正在执行的投递互相覆盖。
