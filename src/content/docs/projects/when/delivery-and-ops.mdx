> **运维重点**：生产可用不只看消息能否投出去，还要能解释失败、观测延迟、执行切换、管理集群并重复部署。

## Sink 插件

`Sink` 统一描述“把到期消息投递到下游”。HTTP 和 Kafka 是第一阶段实现，后续可以增加 gRPC、RocketMQ 或其他类型。

新增 Sink 应只增加实现和注册声明，不修改 When 核心调度流程。

## 失败分类与重试

- 参数或鉴权错误：通常不应无限重试；
- 网络超时、临时不可用：按退避策略重试；
- 下游明确拒绝：记录原因并进入失败或人工处理；
- 达到最大次数：停止自动重试，保留完整投递记录。

## 可观测性

至少包含：

- 请求量、提交量、各状态存量；
- 投递延迟、耗时、失败率；
- 节点数、选举、故障切换和上下线次数；
- Redis、ETCD 操作成功与失败；
- 带 `trace_id` 的结构化日志；
- `/health`、`/ready` 和 `/metrics`。

高基数字段如 `message_id` 不应直接作为 Metrics label。

## 管理台

业务 API 提供 Submit、Query、Cancel；管理 API 提供时间轮、消息、节点和集群视图。管理台只调用管理 API，不直接操作 ETCD、Redis 或内部对象。

## 部署形态

| 形态                | 用途                                       |
| ------------------- | ------------------------------------------ |
| Docker Compose      | 本地开发、依赖和多节点演示                 |
| Jar / Docker 单节点 | 最小功能验证和低可用场景                   |
| Kubernetes          | 多节点生产部署、探针、Secret、PDB 和扩缩容 |
