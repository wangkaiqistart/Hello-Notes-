> **验收重点**：先证明单次对话、工具调用、记忆和接口闭环，再扩展分布式和运行治理，不用“模块数量”代替可运行证据。

## 最小验收闭环

1. 配置一个 Provider 并完成一次模型调用。
2. ReAct 调用一个工具，接收结果并结束循环。
3. 多轮会话能保留上下文。
4. 长期记忆写入后可在新会话检索。
5. CLI 和 Web Service 使用同一套 Agent 引擎。
6. 工具权限、超时、错误和日志可检查。

## 后续演进

- Provider 多模型路由与限流；
- Memory 的结构化、语义检索和生命周期；
- Tool 的沙箱、审计和业务系统连接；
- 多实例、任务调度和高可用；
- 管理台、指标、追踪和部署自动化。

## 不把什么当验收

- 只编译通过；
- 只返回一段看似合理的文本；
- 只展示 Demo 截图；
- 只统计模块和代码行数。
