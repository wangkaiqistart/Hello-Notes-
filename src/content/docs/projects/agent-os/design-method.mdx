> **设计重点**：先定义系统边界和公共契约，再实现 Provider、ReAct、Memory、Tool、Sandbox 与入口；每个模块都必须能独立验证。

## 设计顺序

1. 先写项目目标、非目标和验收标准。
2. 画出入口、运行时、能力层和基础设施的边界。
3. 为 Provider、Memory、Tool、Channel 和 Storage 定义稳定接口。
4. 按依赖关系实现最小闭环，而不是按页面或类的数量推进。
5. 用测试、构建、运行日志和 Review 证明每一步结果。

## 五个核心组件

- Provider 屏蔽模型厂商差异；
- Loop 负责调度和终止；
- Memory 管理当前状态和跨会话事实；
- Tools 连接外部世界；
- Environment 提供文件、Shell、网络和凭证边界。

[![Agent 运行底座的五个组件：Provider、ReAct Loop、Memory、Tools 和 Environment](/images/ai-programming/notes/agentos-components.svg)](/images/ai-programming/notes/agentos-components.svg)

## 三条工程原则

- **接口先行**：先表达能力和约束，再选择实现。
- **最小权限**：工具、路径、命令、网络和密钥默认收紧。
- **证据验收**：不能用 Agent 的自我描述替代测试和运行证据。
