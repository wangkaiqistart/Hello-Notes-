> **架构重点**：把模型、循环、工具和状态拆开，让每个变化点有清晰接口；先保证边界稳定，再替换具体实现。

## 关键决策

### Provider 显式映射

上层传入 Provider 和 Model 配置，由 ProviderService 选择具体 `ChatModel`。ReAct 不直接依赖厂商 SDK，换模型只改配置或映射。

在自建循环方案里，Spring AI 只承担协议适配和 `@Tool` Schema 生成。Tool 调度与执行由 AgentOS 接管，需要关闭框架的自动 Tool 执行，避免同一调用被执行两次。这是该项目的集成边界。

[![AgentOS 使用 Spring AI 的边界：复用 Provider 适配和 Tool Schema 生成，由自建 ReActLoop 和 ToolExecutor 控制执行](/images/ai-programming/course/agentos-boundary.svg)](/images/ai-programming/course/agentos-boundary.svg)

_“禁用”针对 AgentOS 自建循环的配置。_

### ReAct 只负责编排

循环负责转圈、累积状态、判断终止；Prompt 组装、模型调用和工具执行分别交给专门模块。默认需要最大轮数和无工具调用的结束条件。

[![ReAct 流程：接收消息、组装 Prompt、调用模型；有 Tool 调用则执行并回填历史后继续循环，否则返回最终响应](/images/ai-programming/course/agentos-react.svg)](/images/ai-programming/course/agentos-react.svg)

_最大轮数、超时和异常出口也需要实现，图中省略了这些分支。_

### Memory 分层

- Session 保存当前对话和工具结果；
- 长期记忆保存跨会话事实、经验和偏好；
- 上下文构建器决定本轮注入哪些内容。

对引擎只暴露统一的 `MemoryService`，由它委托会话记忆和长期记忆组件，避免循环直接操作两套存储。

[![MemoryService 统一门面：ReAct 通过一个接口访问 SessionManager 会话记忆和 LongTermMemory 长期记忆](/images/ai-programming/course/agentos-memory.svg)](/images/ai-programming/course/agentos-memory.svg)

_图中仅展开会话记忆与长期记忆两个组件，统一门面负责协调访问。_

### Tool 统一抽象

内置工具、Skill/MCP 和 Java Bean 都包装成统一 Tool 描述和执行接口，由 Registry 管理发现、参数校验、权限、超时和审计。

### 状态持久化

会话、Profile 和必要的运行记录进入结构化存储；工作区文件和 Skill 保留文件系统形态；密钥使用外部配置。

## 取舍原则

1. 先接口后实现。
2. 先单体可验证，再考虑分布式。
3. 能复用成熟组件就不重复造轮子。
4. 高风险能力默认关闭并显式授权。
