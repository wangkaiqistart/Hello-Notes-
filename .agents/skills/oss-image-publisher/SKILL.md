# OSS 图片发布

## Goal
目标：
用可复用、密钥安全的流程，把一个或多个本地图片文件转换成稳定的阿里云 OSS 链接。这个 skill 只返回链接；文档插入、知识库整理和 Markdown 编辑由其他 skill 处理。

## Workflow
工作流：
1. 阶段 1：确认输入边界
   - 找到需要上传的本地图片路径。
   - 确认用户需求是“上传图片并返回链接”，不是编辑知识库内容。
   - 通过门禁：每个源文件都存在，并且输出格式明确，支持 `text`、`json`、`markdown`。
2. 阶段 2：确认 OSS 目标
   - 从环境变量或明确的命令参数读取 OSS 配置。
   - 必填目标配置：存储桶和访问域名。
   - 真实上传时必填密钥：AccessKey ID 和 AccessKey Secret；演练模式不需要。
   - 通过门禁：AccessKey 或 Secret 不写入仓库文件、提示词、日志或生成文档。
3. 阶段 3：执行上传
   - 使用图片路径运行 `scripts/upload_image_to_oss.py`。
   - 默认对象路径由前缀、日期、文件名和内容哈希生成；只有用户明确指定单个对象路径时才使用 `--key`。
   - 通过门禁：命令执行成功，并为每张输入图片返回一个链接。
4. 阶段 4：返回链接
   - 按用户要求的格式返回上传后的链接。
   - 如果用户没有指定格式，默认返回纯链接，方便交给其他工作流继续处理。
   - 通过门禁：最终回复只包含链接和必要的简短提醒，不编辑任何文档。

## Decision Tree
决策树：
- 如果用户要求上传图片并返回链接，使用这个 skill。
- 如果用户要求“上传图片并插入 Markdown、MDX 或文档”，这个 skill 只负责上传步骤，然后把返回链接交给对应的文档或知识库 skill。
- 如果用户只想整理、改写或放置已有图片链接，不需要新上传 OSS，不使用这个 skill。
- 如果用户在聊天里提供密钥，不要持久化保存；真实上传前让用户把密钥放到环境变量中。
- 如果存储桶是私有的，而用户需要公开访问链接，先确认公开访问域名、CDN/CNAME、存储桶策略或对象 ACL，再承诺链接可访问。

## Constraints
约束：
- 永远不要提交、保存、打印或记录 AccessKey Secret。
- 优先使用环境变量，不把密钥放在命令参数里，因为 shell 历史可能保留命令参数。
- 默认只接受能识别为图片的本地文件。
- 这个 skill 不修改知识库文件、飞书文档、Markdown 文件或 MDX 文件。
- 不创建或管理 OSS 存储桶；默认存储桶已存在，RAM 用户有 `oss:PutObject` 权限。
- 使用单文件 PutObject 上传；超过 5 GB 的对象不在当前范围内，需要专门的分片上传流程。

## Validation
验证：
- 必跑检查：
  - `python3 scripts/upload_image_to_oss.py --help`
  - 用本地图片和临时存储桶/访问域名配置跑演练模式。
  - 只有在 OSS 环境变量齐全且允许联网执行时，才跑真实上传。
- 成功标准：
  - 每张请求上传的图片都有一个返回链接。
  - JSON 输出包含源文件、对象路径、存储桶、访问域名、链接、内容类型和大小。
  - 输出内容和变更文件中不出现任何真实密钥。
- 常见失败排查：
  - 缺少 `ALIYUN_OSS_BUCKET` 或 `ALIYUN_OSS_ENDPOINT`。
  - 真实上传时缺少 `ALIYUN_OSS_ACCESS_KEY_ID` 或 `ALIYUN_OSS_ACCESS_KEY_SECRET`。
  - 存储桶私有，或公开访问域名配置错误。
  - RAM 用户缺少 `oss:PutObject` 权限。
