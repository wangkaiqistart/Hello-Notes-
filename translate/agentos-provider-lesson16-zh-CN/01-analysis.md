## 需澄清的原文问题

1. 原文 OryxOS 是课程命名，文档统一称 AgentOS；代码中的 oryxos、.oryxos 和 OryxTool 保留并标注，不能冒充当前工程路径。
2. 关闭工具自动执行是架构要求，课件 API 为伪代码；不能保证启用双循环一定每次重复执行。
3. ChatModel 是模型客户端，provider 与实例的数量关系是课程配置选择，不是框架限制。
4. 原文 chat 骨架没有显式传 model 和 temperature，读者实现时必须补上，不能只记录到审计。
5. Profile 单个加载失败与调用时未知 provider 都需报错，但作用范围不同。
6. @Tag 本身不配置 Maven 分组；*IT 的发现、插件和命令需要匹配。
7. 原文捕获 RuntimeException 包住审计，不能据此保证审计失败时模型成功仍算成功或记录不丢；仅标注需定义独立策略。
8. SQLite 迁移能力不宜绝对化为“很弱”；强调显式迁移与真实 SQL 测试。
