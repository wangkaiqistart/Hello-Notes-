# 精翻审校

## 准确性

- 逐段对照来源，三段共覆盖 12 个二级章节，保留全部代码块、默认值、重载及实现限制。
- call() 的触发时机：来源首例说 call() 直接发送请求，后文又说明取结果方法才执行。译文统一采用后者；流式响应补明订阅时执行。
- 多模型：区分 ChatClient 和 ChatModel 的 @Primary，不能用前者解决后者的注入歧义。
- 流式转换示例：统一 ActorsFilms/ActorFilms，去除 this 字段与局部变量混用；原样保留其他 API。
- 多 OpenAI 兼容端点示例已核对 v2.0.2 的 OpenAiChatModel 源码，Builder 使用 options()。模型名称沿用来源，使用前需确认提供方支持，未执行 Java 编译或真实模型调用。
- 来源 EntityParamSpec 锚点不存在，修订为本文对应小节；实现说明等本文内链接也改为中文锚点。
- 默认配置不能笼统理解为整组替换：补明具体合并行为由对应 API 决定，options 中未指定项保留默认值。
- 对照 ChatModel 文档，补明增量合并发生在 ChatClient；直接调用 ChatModel 时，非空 Prompt options 是完整配置，null 才使用模型默认值，图中不再添加模型层的逐字段合并。
- Advisor 示例不能仅凭添加顺序推断，保留 order 约束，并限定记忆与检索先后由实际 order 决定。
- 实现说明沿用来源版本，避免将 Servlet/Reactive 限制推广至所有版本和所有提供方。
