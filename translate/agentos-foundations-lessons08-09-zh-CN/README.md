## 关键工程判断

- 目标项目仍是 Maven 骨架与工程基线，业务类与业务迁移尚未实现。文中能力均以职责、实现要求或目标范围表述，状态单独说明。
- 全局聊天连接在 application.yaml，Agent 显式选 provider 和 model，遵循用户前面已确认的配置分工。目标项目仍保留全局默认模型等字段，本次未修改 Java 项目；差异继续由 Provider 复核记录跟踪。
- 当前设计同时存在启动扫描与后续热注册路线。两篇入门文档只解释定义与加载关系，不承诺热更新已可用。
- 当前 Chat Memory 在线参考已说明 MessageWindowChatMemory 按完整轮次淘汰消息；因此不复述旧的“框架必然拆开工具消息”判断。自管会话的理由是完整持久化、状态关联和应用控制，裁剪仍需保持协议完整。
- 模型推理次数、工具调用次数、Provider 额外尝试是不同预算，分别限制；模型输出不能作为工具成功证据。
- 虚拟线程不等于无限容量；数据库、服务配额、下游连接与业务权限都要独立治理。
- 默认长期记忆文件与本地工作区不天然具备多租户隔离或多实例共享能力。
