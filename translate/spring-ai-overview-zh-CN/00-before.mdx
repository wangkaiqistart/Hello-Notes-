Spring AI 用于简化 AI 应用开发，核心是**将企业数据和业务 API 与 AI 模型连接起来**。它借鉴了 LangChain 和 LlamaIndex 的设计思路，但不是这些框架的直接移植。

## 解决什么问题

企业应用拥有自己的数据和 API，生成式 AI 提供理解与生成能力。Spring AI 在两者之间提供统一抽象，帮助应用接入模型、提供上下文，并调用业务能力。

同一种抽象可以有多种实现，因此切换模型或向量数据库时，通常只需少量代码调整。下图展示了应用的数据、API 与生成式 AI 之间的连接关系。

## 核心能力

| 能力             | 作用                                                                                                               |
| ---------------- | ------------------------------------------------------------------------------------------------------------------ |
| 模型接入         | 支持聊天、Embedding、图像生成、语音转写、语音合成和内容审核；聊天等 API 支持同步与流式调用，也可使用模型特有功能。 |
| 结构化输出       | 将模型输出映射为 Java 对象（POJO），便于程序继续处理。                                                             |
| 向量数据库       | 提供统一访问接口和类似 SQL 的元数据过滤语法，支持 PGvector、Redis、Elasticsearch、Milvus 等。                      |
| 工具调用         | 模型可请求执行应用侧的工具或函数，获取实时信息或完成操作。                                                         |
| MCP              | 接入外部 MCP 服务，也可将 Spring 服务暴露给 AI 应用使用。                                                          |
| 文档处理         | 通过 ETL 流程完成文档读取、转换和写入，为检索准备数据。                                                            |
| ChatClient       | 通过链式 API 调用聊天模型，用法类似 `WebClient` 和 `RestClient`。                                                  |
| Advisors         | 封装常见 AI 应用模式，处理发送给模型和从模型返回的数据，便于复用。                                                 |
| 对话记忆与 RAG   | 为多轮对话提供历史上下文，通过检索补充文档知识，构建文档问答应用。                                                 |
| 可观测性与评估   | 观察 AI 调用过程，评估生成内容，辅助发现幻觉问题。                                                                 |
| Spring Boot 集成 | 为模型和向量数据库提供自动配置与 Starter。                                                                         |

模型提供方包括 Anthropic、OpenAI、Microsoft、Amazon、Google 和 Ollama 等。具体支持的模型能力与配置方式，以各提供方章节为准。
