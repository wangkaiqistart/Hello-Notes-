# 总览初稿审校

## 准确性

- “应用可以用少量代码调整来切换模型或向量数据库”比旧稿更绝对，源文的可移植抽象不等于所有提供方功能完全一致。保留旧稿“通常”的限定更稳妥。
- 模型接入行把聊天、图像、Embedding 与同步/流式并列，可能被读成每一种模型均支持两种调用。应保留框架支持两类调用的含义，同时限定具体方式由模型和提供方决定。
- Advisors 初稿补回不同模型和场景间复用，符合源文，接受。
- 将可观测性与模型评估分为两行，符合源文分别列出的两个功能，接受。这是功能边界澄清，不能将旧稿描述为事实错误。
- 模型、工具执行主体、MCP、ETL 与原文一致；不把已有正确的链式 API 译法声称为本轮纠错。

## 中文表达

- 模型接入行信息偏多，首次释义、调用方式、模型类型不应挤成一个长句。可将语音及审核能力放到表后，与提供方说明一起呈现。
- “可跨向量存储提供方复用的 API”准确但冗长，可保留关键的跨提供方语义并收紧表述。
- 对话记忆与 RAG 可以继续共用一行，但用分号区分历史上下文和检索资料。

## 注释与取舍

- 数据库列表仍用 PGvector、Redis、Elasticsearch、Milvus 举例，并恢复官方完整列表链接；这是延续既有简明风格的取舍，不声称穷举。
- 两张原图及其位置、图注保留；品牌标识不需要中文改绘。
- 仅更新正文与核验日期，不改变路由、frontmatter 或导航。

## 结论

无须推倒重译。采纳初稿的术语、语义补全和章节链接；修正跨提供方切换及流式支持的限定，再进行中文润色。
